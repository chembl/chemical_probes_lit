# Running the literature pipeline with external data

The public repository contains the analysis code. Keep downloaded inputs, run outputs,
and your institutional Slurm scripts outside the checkout. You only need one Git
repository; the private scripts folder is an ordinary directory on your cluster.

## Storage layout

```text
/project/chemical_probes/
├── code/                       # This repository checkout (can be elsewhere)
├── cluster/                    # Private .sh scripts, environment setup, settings
├── inputs/
│   ├── probesSubset.csv        # HQ dictionary: tab-separated despite its suffix
│   ├── dated_evidence/         # Optional historical/record-level alternative
│   ├── disease_term_black_list.tsv  # Plotting input: comma-separated
│   ├── probe_references.csv    # Plotting input: comma-separated
│   └── opentargets/snapshot_001/
│       ├── literature_match/
│       ├── association_by_datasource_indirect/
│       ├── disease/
│       ├── clinical_target/
│       ├── clinical_indication/
│       └── download_manifest.json
└── runs/analysis_001/
    ├── intermediate/
    ├── results/
    ├── figures/
    ├── tables/
    └── logs/
```

Use your institution's actual project-storage path. Inputs and outputs must be
accessible from compute nodes; the Spark merge helper uses ordinary filesystem
paths, not `s3://`, `gs://`, or HDFS URIs. Keep `cluster/` on backed-up storage;
files there have no Git history. Do not place it inside the public checkout.

## Environment and path setup

Install dependencies from the repository's `requirements.txt` into an external
Python environment, and activate it before running commands. Spark also requires
a compatible Java installation. The requirements file currently pins PySpark 4.1.2;
the historical manuscript environment used PySpark 3.3.1 and Python 3.11.7.
Those are different environments: this path refactor does not establish that their
results or compatibility are equivalent. Use a validated cluster environment for
production, and record its versions.

Set these variables in your shell, or in a private file such as
`/project/chemical_probes/cluster/paths.sh` that each job sources:

```bash
export CODE_DIR="/project/chemical_probes/code"
export INPUT_DIR="/project/chemical_probes/inputs"
export OT_DIR="$INPUT_DIR/opentargets/snapshot_001"
export RUN_DIR="/project/chemical_probes/runs/analysis_001"
export PROBES_FILE="$INPUT_DIR/probesSubset.csv"
export DATED_EVIDENCE_DIR="$INPUT_DIR/dated_evidence"  # Optional record-level mode only

mkdir -p "$OT_DIR" "$RUN_DIR"/{intermediate,results,figures,tables,logs}
```

Replace the example paths before executing. An existing checkout can stay where
it is: set `CODE_DIR` to its absolute path. These variables are expanded by the
shell in the commands below; Python steps do not automatically read them.
Use a new `RUN_DIR` for each analysis, and a new snapshot directory for a fresh download.

All steps require an explicit destination (`--output`, or `--output-dir` for step 0).
Parents are created automatically. Relative paths are relative to the current
working directory; absolute paths are recommended. Existing output files are
replaced, so do not run two jobs against the same output filename. Spark TSV merge
parts use unique temporary directories beside the output and are cleaned up after
normal success or failure. Allow disk space for both part files and the merged TSV.
Spark's own spill/cache storage is separate and should be configured through your
cluster's Spark environment, for example `SPARK_LOCAL_DIRS` for local-mode jobs.

## Inputs that must be prepared separately

Step 0 downloads only the five Open Targets datasets shown above. You must also
provide:

- The HQ probes dictionary built using `3_probesHQ/probes_hq_dataset.ipynb`.
  It is tab-separated and includes `CHEMBLID`, `SYNOMS`, `GENE`, and the other
  probe metadata used by the pipeline. Export/copy it to `PROBES_FILE`.
- Optional: record-level dated evidence for `--datedevidence` mode. The recommended
  step 5 uses the association time series downloaded by step 0 instead.
- For the plotting notebook, the curated disease exclusion list and probe
  reference table. These are not generated by steps 0–7. Preserve the filenames
  shown above, or edit the notebook's corresponding input paths. The exclusion
  list must contain `diseaseId`; both files are read as comma-separated tables.

## Execute steps 0–7 in order

Run the following commands in the configured Python environment, on suitable
allocated compute resources. Every command can be executed from any directory.
Run each step only after its predecessor succeeds. `--help` describes its arguments
without starting Spark or downloading data.

### 0. Download Open Targets inputs

```bash
python "$CODE_DIR/2_probesLit/0_download_OT_files.py" \
    --output-dir "$OT_DIR" \
    --release 26.09 \
    --literature-release latest
```

These defaults select release `26.09` for
association/disease/clinical data and `latest` for literature. `latest` changes over
time. For reproducibility, choose a literature release where the required dataset
is available, or supply its complete server directory using `--literature-dir`.
Directory layouts can differ between releases; an unavailable path causes the download
to fail. This change does not verify upstream availability or schema compatibility.

The downloader writes `download_manifest.json` after all five downloads succeed,
recording requested releases, source URLs, filenames and completion time. It does not resolve
`latest` to a fixed release or calculate checksums. Retain the downloaded snapshot
and record checksums separately if exact input identity is required. Downloads
replace same-named local files. Stale parquet filenames are rejected; interrupted
files are retried from the beginning rather than resumed. Use an empty destination
for a new snapshot. All five listings are validated before any data files are fetched.
Use `--check-only` with the same arguments to validate listings without downloading.
Files are streamed to `.part` files and renamed only after successful transfers.

### 1. Find articles mentioning HQ probes and retain their annotations

```bash
python "$CODE_DIR/2_probesLit/1_get_ner_hq_probes.py" \
    --matches "$OT_DIR/literature_match" \
    --probes "$PROBES_FILE" \
    --intermediate-output "$RUN_DIR/intermediate/epmc_ner_results_hq_probes.tsv" \
    --output "$RUN_DIR/intermediate/1_epmc_ner_results_hq_probes_all_sent.tsv"
```

The intermediate file contains HQ probe mentions; the final file contains all
annotations for those articles. If omitted, `--intermediate-output` defaults to
`<output>.hq_mentions.tsv`. It must differ from the final output path.

Step 1 expects the public `literature/match` parquet schema with `pmid`, `label`,
`mappedId`, `type`, `pubDate`, `section`, and `text`. It exports **`mappedId` as
`label_id`**, so downstream TSV column names and step 2 arguments are unchanged.
`mappedId` is already one mapped entity ID per row; do not explode `entityIds`
again. Distinct mapped IDs for the same mention are retained, while identical
projected rows are deduplicated as before. No new `isMapped`/`isValid` filtering
is introduced: use the public valid-match dataset, not failed matches. Legacy
inputs containing only `keywordId` fail with an explicit schema error.

### 2. Extract probe–target–disease triplets

```bash
python "$CODE_DIR/2_probesLit/2_get_triplets.py" \
    --input "$RUN_DIR/intermediate/1_epmc_ner_results_hq_probes_all_sent.tsv" \
    --probes "$PROBES_FILE" \
    --output "$RUN_DIR/intermediate/2_ner_probes_triplets.tsv"
```

### 3. Filter for accepted probe targets

```bash
python "$CODE_DIR/2_probesLit/3_filter_targets.py" \
    --input "$RUN_DIR/intermediate/2_ner_probes_triplets.tsv" \
    --probes "$PROBES_FILE" \
    --output "$RUN_DIR/intermediate/3_ner_probes_triplets_ptpairs.tsv"
```

This step queries Ensembl, so the compute node needs network access. It retries
HTTP 429/5xx, connection failures and malformed responses up to five times with
bounded delays and request timeouts. A request that remains unresolved stops the
job before replacing the output, preventing silent target loss. Only an explicit
symbol-not-found response is reported as a missing mapping.

Successful mappings are saved after each lookup in
`intermediate/ensembl_gene_mappings.json` by default. Reuse this cache for retries;
use a fresh cache for a new analysis because the Ensembl endpoint is not release-pinned.
Optional `--gene-cache PATH` selects another location. The output's
`.mapping_report.json` records mapping coverage, missing symbols and input/output
row counts. Review these counts before using downstream results. The existing
exact GENE-to-ID matching policy is retained.

### 4. Add Open Targets evidence

```bash
python "$CODE_DIR/2_probesLit/4_get_OT_evidence.py" \
    --input "$RUN_DIR/intermediate/3_ner_probes_triplets_ptpairs.tsv" \
    --evidence "$OT_DIR/association_by_datasource_indirect" \
    --output "$RUN_DIR/intermediate/4_ner_probes_triplets_ptpairs_ev.tsv"
```

### 5. Add dated evidence

```bash
python "$CODE_DIR/2_probesLit/5_get_OT_dated_evidence.py" \
    --input "$RUN_DIR/intermediate/4_ner_probes_triplets_ptpairs_ev.tsv" \
    --associations "$OT_DIR/association_by_datasource_indirect" \
    --release 26.09 \
    --output "$RUN_DIR/intermediate/5_ner_probes_triplets_ptpairs_evd.tsv"
```

### 6. Add disease therapeutic areas

```bash
python "$CODE_DIR/2_probesLit/6_map_disease_therapeutic_area.py" \
    --input "$RUN_DIR/intermediate/5_ner_probes_triplets_ptpairs_evd.tsv" \
    --otdisease "$OT_DIR/disease" \
    --output "$RUN_DIR/intermediate/6_ner_probes_triplets_ptpairs_evd_ta.tsv"
```

### 7. Add maximum disease-specific clinical stage

```bash
python "$CODE_DIR/2_probesLit/7_get_drug_max_phase.py" \
    --input "$RUN_DIR/intermediate/6_ner_probes_triplets_ptpairs_evd_ta.tsv" \
    --clinical-target "$OT_DIR/clinical_target" \
    --clinical-indication "$OT_DIR/clinical_indication" \
    --output "$RUN_DIR/results/7_ner_probes_triplets_ptpairs_dr.tsv"
```

All step 1–7 outputs are **TSV files**, not comma-separated CSV files.

## 8. Classify article types

```bash
python "$CODE_DIR/2_probesLit/8_classify_article_types.py" \
    --input "$RUN_DIR/results/7_ner_probes_triplets_ptpairs_dr.tsv" \
    --output "$RUN_DIR/results/8_ner_probes_triplets_reviews.tsv" \
    --cache "$RUN_DIR/results/pubmed_article_types.sqlite"
```

Keep the SQLite cache on the cluster and reuse it for retries. Unresolved PubMed
requests remain unknown, not primary research. The default notebook policy excludes
confirmed reviews and retains unknowns; use `PROBES_REVIEW_POLICY=classified_non_reviews`
for a separate sensitivity analysis. Classification as primary means a returned
PubMed type list without the `Review` label, not independent study-design validation.

## 9. Prepare plotting data

```bash
python "$CODE_DIR/2_probesLit/9_prepare_plotting_data.py" \
    --input "$RUN_DIR/results/8_ner_probes_triplets_reviews.tsv" \
    --output "$RUN_DIR/results/plotting/plotting_data.tsv.gz" \
    --chunk-size 10000
```

This streams a column-reduced copy, preserving all rows, their order and sentence
text. It removes unused metadata such as large control and synonym payloads without
changing the source. The adjacent `.manifest.json` records row counts, columns,
source size/mtime, article classifications and date policies. Require a successful
job and fresh manifest; compare its row count with step 8's log. Optional
`--triplets "$RUN_DIR/intermediate/2_ner_probes_triplets.tsv"` adds exact diagnostic
counts, at the cost of another full scan and temporary disk space.

## 10. Plot locally

Copy `plotting_data.tsv.gz` **and its manifest** to the corresponding local run's
`results/plotting/` folder. Also provide the run's dictionary, disease exclusion
list, probe reference table and ChEMBL 37 SQLite database. The large intermediate
TSVs and PubMed cache can stay on the cluster. Compressed size is not a memory
estimate: the notebook loads pandas data and creates additional copies.

```bash
export PROBES_INPUT_DIR="/path/to/local/run/inputs"
export PROBES_RUN_DIR="/path/to/local/run"
export PROBES_FILE="$PROBES_INPUT_DIR/probesSubset.csv"
export PROBES_ANALYSIS_FILE="$PROBES_RUN_DIR/results/plotting/plotting_data.tsv.gz"
export CHEMBL_SQLITE="/path/to/chembl_37.db"
export PROBES_REVIEW_POLICY="exclude_reviews"
cd "$CODE_DIR/2_probesLit"
jupyter lab 10_plotting_data.ipynb
```

Start a fresh kernel and run cells in order. Figures go to `figures/`, tables to
`tables/`, and derived datasets to `results/` under the selected run. Keep the original
manuscript notebook, inputs and figures separately; saved notebook outputs are not
results of a new run. Figure styling and fixed cutoffs are retained, while data,
rankings and counts can change. Jitter uses a fixed seed. The manuscript used
ChEMBL 35; this run uses ChEMBL 37.

## Temporal evidence dates

Step 5 uses the same release's `association_by_datasource_indirect` files as step 4.
It selects the earliest non-null `timeseries.year` with **positive
`yearlyEvidenceCount`**, no later than the pinned release year. Padding years,
undated bins and novelty scores are not evidence dates. These are consolidated OT
dates, not necessarily publication dates. Indirect associations include evidence
propagated through the disease ontology. No private bucket is needed in this mode.

Alternatively, pass `--datedevidence PATH --release YY.MM` for record-level Parquet
with disease, target and datasource IDs. Choose the first valid date **per record**
in the order **publicationYear → curationYear → studyYear → evidenceDate**, using
whichever fields exist, then aggregate. Separate historical year arrays cannot
reconstruct that per-record rule. Missing, malformed and future dates do not become
invented dates, and historical datasource names are never silently renamed.

The output adds `firstEvidenceYear`, `allEvidenceYears`, `evidenceYearPolicy`,
`earliestYearOrigins`, `datedEvidenceCount`, `undatedEvidenceCount` and
`datedEvidenceStatus`. Status distinguishes matched, dates_missing, pair_absent,
source_absent and no_association. Counts repeat on literature rows: deduplicate
association keys before summing. The `.dated_coverage.json` sidecar records the
input, release, date policy and source coverage; inspect it before plotting.

The notebook takes the earliest selected year across non-literature sources per
pair. A positive lag means probe literature precedes the **available dated evidence**,
not all published knowledge. The manuscript used the minimum across three historical
date arrays; report this methodological change. Separate date-type Venn plots are
omitted when OT provides only consolidated dates. For a date-only update, preserve
old results, reuse step 4 and rerun steps 5–9 to new outputs. The updated notebook
rejects extracts missing the new date fields.

OT's [year extraction](https://github.com/opentargets/pipeline/blob/5862cde5fc639bb740f502b5156993120155bc18/pts/src/pts/pyspark/associations_utils/evidence.py)
and [time-series aggregation](https://github.com/opentargets/pipeline/blob/5862cde5fc639bb740f502b5156993120155bc18/pts/src/pts/pyspark/associations_utils/association.py)
were inspected at that commit, not asserted to be the exact 26.09 build. The downloaded
26.09 schema was checked separately. Retain the download manifest and update both
OT_DIR and `--release` together; the argument alone cannot verify a local snapshot.

## Clinical stages and association sources

Step 4 normalizes `aggregationValue` to datasourceId and `associationScore` to score,
using datasource-level rows. Unknown sources fail rather than receiving guessed
datatypes. Mapping provenance is recorded in `helpers/association_schema.py`.
Step 7 links drugs to targets with Clinical Target, then uses Clinical Indication
for the **drug–disease-specific** stage; the target-level maximum is not substituted.

`clinicalStageRank` orders categories and is not a numeric clinical phase. Approval
is distinct from phase IV; UNKNOWN is distinct from no matched indication. Bubble
annotations use short labels (1, 1/2, 2, 2/3, 3, 4, A for approval, n for no match)
with a key. ChEMBL probe-level maxPhase is a separate measurement. The existing
manuscript category ranking omits genetic_literature, so its residual no_evidence
category must not be interpreted as universally lacking evidence.

## Optional manuscript dictionary supplement

`helpers/supplement_probe_dictionary.py` is a standalone input-preparation command, not a
numbered pipeline step. Give it current and manuscript TSVs with the same columns,
a reviewed JSON plan, and a new output path. The plan contains `restore_ids`
(append complete manuscript rows), `repair_ids` (repair missing IDs only on exact
InChIKey matches) and `alias_owners` (explicit synonym-to-ID assignments).

```bash
cd "$CODE_DIR/2_probesLit"
python -m helpers.supplement_probe_dictionary \
    --current /path/to/current/probesSubset.csv \
    --manuscript /path/to/manuscript/probesSubset.csv \
    --plan /path/to/supplement_plan.json \
    --output /path/to/new_dictionary/probesSubset.tsv
```

Existing destinations are refused; input files remain unchanged. Keep the output,
its `.provenance.tsv` (one-based data-row origins) and `.manifest.json` (hashes,
plan and conflicts). Historical inclusion does not certify current HQ status.
Steps 1–2 trim synonym whitespace; step 2 changes only chemical entities and retains
OT IDs for unresolved ambiguous synonyms, reporting conflicts in a sidecar.
Use the supplemented dictionary in a **new run**, rerunning steps 1–9 and using the
same dictionary locally. Restored dictionary entries do not guarantee recovered
literature, and salts must not automatically count as independent probes.

## Cluster execution and checks

Keep Slurm wrappers and institutional paths outside Git. Each wrapper activates
the environment, sources the private path settings and calls the corresponding
numbered script above. Create logs before submission; use `afterok` dependencies
for a tested chain. Keep RUN_DIR and inputs fixed while jobs are queued or running.
Pulling Python changes does not update private wrappers. The date update requires
step 5's `--associations` and `--release` arguments.

```bash
sacct -j JOB_ID --format=JobID,State,ExitCode,Elapsed
head -n 1 "$RUN_DIR/intermediate/5_ner_probes_triplets_ptpairs_evd.tsv"
cat "$RUN_DIR/intermediate/5_ner_probes_triplets_ptpairs_evd.tsv.dated_coverage.json"
cat "$RUN_DIR/results/plotting/plotting_data.tsv.gz.manifest.json"
```

Check for COMPLETED and exit code 0:0, inspect both logs and verify output headers
before proceeding. Use the shared TSV reader/writer: literal backslashes, quoted
text, tabs and newlines must round-trip; never hide parsing errors by skipping rows.
Older article-annotation files may have a `9_` prefix; update wrapper paths together
if renaming them to `8_`, but preserve historical manifests and the SQLite cache.

## Code layout

Numbered scripts and the plotting notebook are the entry points. Shared processing,
I/O and plotting functions—including the existing `tools.py`—live in `helpers/`.
Imports use `from helpers...`; run the notebook from this directory. The dictionary supplement also lives in `helpers/` and is run with
`python -m helpers.supplement_probe_dictionary` from this directory. Moving helpers does not
change script arguments or analysis results. Tests live in the repository's `tests/`.
